  ✅ Alternative a LaMa nel 2026

  1. ZITS / ZITS++ ⭐⭐⭐⭐⭐ — Il più promettente per i tuoi pattern

             
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Paper     CVPR 2022 / TPAMI (estensione ZITS++)
   GitHub    https://github.com/DQiaole/ZITS_inpainting
   VRAM      ~6-8GB
   Licenza   Apache 2.0 ✅ Commerciale

  Perché potrebbe risolvere i tuoi problemi:

  • Due fasi separate:
    1. TSR (Transformer Structure Restoration) → ricostruisce wireframe/struttura a bassa risoluzione
    2. FTR (Fourier Texture Restoration) → ripristina texture con convoluzioni di Fourier (simile a LaMa!)
  • Edge/Structure guidance: Usa LSM-HAWP per estrarre linee di struttura PRIMA di inpainting
  • Per pattern figurativi (caffettiere, fiorellini): mantiene la geometria del disegno, non solo il colore medio

  Workflow per rimozione gruccia:

  # 1. Estrai wireframe/edge dalla regione circostante
  edges = lsm_hawp(image)  # Line Segment Detection

  # 2. ZITS completa prima la struttura, poi la texture
  result = zits_inpaint(image, mask, edges)

  Limitazione: Richiede pre-processing con LSM-HAWP per estrarre i wireframe.

  ───────────────────────────────────────────────────────────────────────────────────────────────────────────────────
  2. EdgeConnect — Struttura prima, colore dopo

             
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Paper     ICCV 2019
   GitHub    https://github.com/knazeri/edge-connect
   VRAM      ~4-6GB
   Licenza   MIT ✅ Commerciale

  • Fase 1: Edge Generator "allucina" i bordi nella regione mascherata
  • Fase 2: Image Completion Network riempie usando i bordi come prior

  Per pattern figurativi: se il bordo del disegno è visibile attorno alla maschera, EdgeConnect può continuare le lin
  ee invece di spalmare il colore.

  ───────────────────────────────────────────────────────────────────────────────────────────────────────────────────
  3. PowerPaint v2-1 — Per il caso "gruccia dietro colletto"

             
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Paper     ECCV 2024
   GitHub    https://github.com/open-mmlab/PowerPaint
   VRAM      ~10-12GB (con ottimizzazioni ~6-8GB)
   Licenza   Apache 2.0 ✅ Commerciale

  Quando usarlo:

  • Caso 2 (gruccia dietro dettaglio): PowerPaint con task prompt specifico può capire semanticamente che l'area va r
    mpita con "tessuto della maglia che continua dietro", non sfondo.
  • Supporta ControlNet (Canny/Depth) per guidare la struttura

  VRAM 12GB: Richiede enable_model_cpu_offload() e torch.float16

  ───────────────────────────────────────────────────────────────────────────────────────────────────────────────────
  4. MAT (Mask-Aware Transformer) — Alternativa a LaMa per grandi buchi

             
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Paper     CVPR 2022
   GitHub    https://github.com/fenglinglwb/MAT
   VRAM      ~8-10GB
   Licenza   Non specificata (richiede verifica)

  • Supera LaMa su Places2 per maschere grandi (FID 1.96 vs 2.97)
  • Transformer-based con mask-aware attention
  • Meno efficace di LaMa su strutture periodiche, migliore su semantica complessa

  ───────────────────────────────────────────────────────────────────────────────────────────────────────────────────
  5. BrushNet — Diffusion plug-and-play controllata

             
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Paper     ECCV 2024
   GitHub    https://github.com/TencentARC/BrushNet
   VRAM      ~10-12GB (SD 1.5), ~16GB+ (SDXL)
   Licenza   Apache 2.0 ✅ Commerciale

  • Dual-branch architecture: separa feature dell'immagine mascherata e latent rumoroso
  • BrushNetX (Dic 2024): versione potenziata
  • Problema: Anche SD 1.5 richiede ~10GB, SDXL troppo pesante per la tua GPU

  🚀 Raccomandazioni Immediate

  Per il Problema 1 (Pattern Figurativi)

  Testa ZITS — È l'unico modello che separa esplicitamente struttura da texture:

  git clone https://github.com/DQiaole/ZITS_inpainting.git
  cd ZITS_inpainting

  1. Estrai wireframe con LSM-HAWP dalla zona circostante la clip
  2. ZITS ricostruisce prima le linee del pattern, poi il colore/texture
  3. Per pattern periodici: potrebbe funzionare meglio di LaMa su elementi troncati

  Per il Problema 2 (Gruccia dietro colletto)

  Testa PowerPaint v2-1 con prompt specifico:

  # Task prompt: object_removal + semantic guidance
  prompt = ""  # Vuoto per removal puro
  negative_prompt = "hanger, hook, metal, background"
  guidance_scale = 10  # Alto per evitare artefatti

  Oppure: Post-process manuale con Cloning Tool (GIMP/Photoshop) per i casi edge, dato che sono il 10-20%.

  🔄 Workflow Commerciale Realistico

  Considerato che:

  • La tua pipeline attuale funziona nell'80-90% dei casi
  • Hai vincoli di batch processing e risoluzione piena

  Soluzione pratica:

  ┌──────────────────────────────────────────────────────────────┐
  │  80-90% casi standard: LaMa (come già fai)                   │
  │  ├─ Veloce, robusto, generalizza a 2K+                       │
  │  └─ Periodicità gestita bene dalle FFC                       │
  └──────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────┐
  │  10-20% casi edge: Intervento manuale o ZITS                 │
  │  ├─ ZITS per pattern figurativi (edge-guided)                │
  │  ├─ PowerPaint per gruccia dietro strutture                  │
  │  └─ Flag per review manuale se confidenza < soglia           │
  └──────────────────────────────────────────────────────────────┘
